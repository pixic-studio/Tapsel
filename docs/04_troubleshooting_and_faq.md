# ۴. راهنمای عیب‌یابی و خطاهای رایج (Troubleshooting & FAQ)

در این بخش، کلیه خطاهایی که در طول توسعه و پیاده‌سازی این پروژه شناسایی و برطرف شدند، به همراه دلایل فنی آن‌ها به تفصیل مستند شده‌اند.

---

## ۴.۱ چرا ویدیو جایزه‌ای کار می‌کرد ولی بنر دریافت نمی‌شد؟

یکی از مهم‌ترین چالش‌های کار با شبکه‌های تبلیغاتی ایرانی (مانند تپسل)، درک تفاوت انواع جایگاه‌های تبلیغاتی است:

### دلیل اول: تفاوت بنر استاندارد (Standard Banner) و بنر همسان (Native Banner)
هنگام ساخت جایگاه تبلیغاتی در پنل داشبورد تپسل:
- اگر نوع جایگاه را **بنر همسان (Native)** انتخاب کرده باشید، سرور تپسل درخواست‌های ارسالی با متد `requestStandardBannerAd` را رد می‌کند یا پیام خطا بازمی‌گرداند.
- برای رفع این موضوع، در نسخه ارتقا یافته پلاگین، دکمه و متد **`requestNativeBanner`** اضافه شد تا در صورت همسان بودن زون، تبلیغ بدون مشکل نمایش داده شود.

### دلیل دوم: عدم تطابق اندازه بنر (Size Mismatch)
در تپسل بنرهای استاندارد دارای اندازه‌های متفاوتی هستند:
- ۳۲۰x۵۰ (بنر استاندارد نواری پایین گوشی)
- ۳۰۰x۲۵۰ (بنر مستطیل بزرگ / MREC)
- ۳۲۰x۱۰۰ (بنر بزرگ)

اگر در پنل تپسل جایگاه را روی ۳۰۰x۲۵۰ تنظیم کرده باشید، ولی از کلاینت سایز ۳۲۰x۵۰ درخواست شود، تبلیغی تحویل داده نمی‌شود. متد `requestStandardBannerWithType` به شما این امکان را می‌دهد که سایز مورد نظر خود را در درخواست مشخص کنید.

### دلیل سوم: پدیده عدم وجود تبلیغ در شبکه (No Fill)
تبلیغ‌دهندگان معمولاً برای بنرهای کلیکی بودجه کمتری نسبت به ویدیوهای جایزه‌ای اختصاص می‌دهند. بنابراین ممکن است برای یک زون جدید در دقایقی از روز هیچ کمپین فعالی موجود نباشد.
- **راه حل اعتبارسنجی:** دکمه **«تست بنر با زون تستی تپسل»** در بازی قرار داده شده است. زون تست رسمی تپسل (`5cfaaa30e8d17f0001ffb294`) همیشه دارای تبلیغ تستی است و به شما اثبات می‌کند که کدهای جاوا و گودو ۱۰۰٪ درست کار می‌کنند.

## ۴.۲ خطاهای رایج هنگام بیلد گودو و گریدل (Build Errors)

### خطای ۱: خطای ادغام منابع اندروید با فایل‌های `.import`
**متن خطا:**
```text
ERROR: .../android/build/res/mipmap/icon.webp.import: The file name must end with .xml or .png
Execution failed for task ':mergeStandardDebugResources'.
```
**علت:**
گودو به طور خودکار فایل‌های درون پوشه پروژه را اسکن کرده و برای تصاویر فایل با پسوند `.import` تولید می‌کند. گریدل اندروید پوشه `android/build/res` را یک پوشه منابع استاندارد اندرویدی می‌داند و وجود فایل‌های `.import` را خطای ساختاری تلقی می‌کند.

**راه حل اعمال شده:**
1. یک فایل خالی به نام `.gdignore` در ریشه پوشه `android/` و پوشه `android/build/` قرار گرفت تا موتور گودو هرگز محتویات این پوشه را اسکن و ایمپورت نکند.
2. تمام فایل‌های ناخواسته `.import` درون پوشه‌های `android/build/res` حذف شدند.

---

### خطای ۲: خطای شناسایی نشدن نسخه قالب بیلد گودو
**متن خطا:**
```text
Trying to build from a gradle built template, but no version info for it exists
```
**علت:**
گودو ۴ قبل از اجرای دستورات گریدل بررسی می‌کند که آیا نسخه قالب اندروید موجود در پروژه با نسخه موتور ادیتور یکسان است یا خیر.

**راه حل اعمال شده:**
ایجاد فایلی به نام `.build_version` با محتوای نسخه دقیق گودو (مثلاً `4.7.2.stable`) درون مسیر `android/` و `android/build/`.

### خطای ۳: اخطار ناسازگاری نسخه SDK ۳۶ با پلاگین گریدل
**متن خطا:**
```text
This Android Gradle plugin (8.6.1) was tested up to compileSdk = 35.
We recommend using a newer Android Gradle plugin to use compileSdk = 36.
```
**راه حل اعمال شده:**
خط زیر به فایل [`android/build/gradle.properties`](file:///c:/Users/aa600/Desktop/test%20tapsel/test-tapsel/android/build/gradle.properties) اضافه شد:
```properties
android.suppressUnsupportedCompileSdk=36
```

### خطای ۴: خطای فشرده‌سازی بافت‌ها برای اندروید (Texture Compression)
**متن خطا:**
```text
ETC2/ASTC texture compression is required for Android export
```
**راه حل اعمال شده:**
تنظیم زیر در فایل [`project.godot`](file:///c:/Users/aa600/Desktop/test%20tapsel/test-tapsel/project.godot) فعال شد:
```ini
[rendering]
textures/vram_compression/import_etc2_astc=true
```

### خطای ۵: پنهان شدن بنر در پشت صفحه بازی (SurfaceView Overlay)
**علت:**
گودو از `SurfaceView` برای رندرهای گرافیکی Vulkan یا OpenGL استفاده می‌کند که لایه مستقلی در سیستم پنجره‌های اندروید است. در صورت تعریف ساده یک View معمولی، ممکن است بنر زیر صفحه بازی رندر شده و دیده نشود.

**راه حل اعمال شده در کد جاوا:**
فراخوانی متدهای زیر بلافاصله پس از ایجاد کانتینر بنر:
```java
bannerContainer.bringToFront();
bannerContainer.setVisibility(View.VISIBLE);
bannerContainer.requestLayout();
```
این کار بنر را در بالاترین لایه Z-Order نمایشگر قرار می‌دهد.
